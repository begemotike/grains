# Decisions log

Numbered, append-only. Each entry says what was decided, why, and what would make us revisit it. Agents and humans editing the code must add an entry when they make a choice the spec left open.

## D1. Name: Grains

The spec calls the product Blink; the owner renamed it Grains before any code existed. Bundle id `net.outofajam.Grains`, repo `begemotike/grains`, CSV files `Grains-2026-W44.csv`, MCP server `grains-mcp`. The spec file is kept verbatim under `docs/spec/` with its original name.

## D2. Monorepo: one Swift package plus one XcodeGen app project

The testable core lives in a Swift package (`GrainsCore`, `GrainsReports`, `GrainsMCP`, `grains-mcp`) so `swift test` runs with no simulator, no signing and no Xcode project. The app target is generated by XcodeGen from `project.yml` (same approach as Steam Shelf) and depends on the package by local path. Why: the spec requires "the core independently testable" and the MCP server is a second process that must share code with the app without sharing a UI framework.

## D3. No App Sandbox in v1 (hardened runtime on)

Distribution is Developer ID + notarization, not the App Store, so the sandbox is optional. It was turned off because: (a) the bundled `grains-mcp` is launched by Claude Code / Claude Desktop as an ordinary process and must read the same database file the app writes; a container path works but is fragile and confusing in client configs; (b) the user-chosen CSV export folder would need security-scoped bookmarks; (c) Sparkle needs XPC exceptions when sandboxed. Revisit if we ever target the App Store. Hardened runtime stays on in Release.

## D4. Database location

`~/Library/Application Support/Grains/grains.sqlite` (WAL mode). Shared by the app (read/write) and `grains-mcp` (read-only, `SQLITE_OPEN_READONLY`, WAL makes concurrent readers safe). Override with `GRAINS_DB_PATH` for tests and development.

## D5. Raw SQLite3 via a thin internal wrapper, no ORM

The schema is one table plus a key/value table. A dependency such as GRDB would add a large framework to notarize and re-sign for a dozen queries. The wrapper is ~200 lines, fully covered by tests, and uses prepared statements only.

## D6. Durations are computed, never authoritative

`duration_seconds` exists as a stored column for CSV/MCP convenience but is recomputed from `started_at`/`stopped_at` on every write, and every total, chart point and export column is built from `Entry.seconds(within:asOf:)`. This is what makes midnight/week-boundary splitting and backdated corrections deterministic.

## D7. Timer survives everything except an explicit stop

Closing the overlay, switching apps, locking, sleeping and quitting the app do **not** stop a running entry; the row simply has `stopped_at NULL` and absolute timestamps. On relaunch after a clean quit the entry is still running from its original start. Only a crash (no clean-shutdown marker) triggers recovery (D8).

## D8. Crash recovery: stop at last heartbeat, flag, never invent time

While an entry runs the app writes a heartbeat every 30 s. On launch, if an entry is running and the previous session did not shut down cleanly, the entry is stopped at the last heartbeat and `metadata.recovered` is set (last heartbeat, noticed-at, reconciled=false). The overlay shows a one-line "recovered" notice with Resume. The gap between heartbeat and launch is uncertain and is not counted. A clean quit clears the heartbeat and leaves the entry running (D7).

## D9. Live elapsed display uses monotonic time, records use wall-clock

The running-session counter in the overlay is driven by `ContinuousClock` offsets from the moment the engine observed the start, so a wall-clock jump (NTP, time-zone travel, manual change) does not make the counter jump backwards or forwards mid-session. Stored records use absolute `Date`s. If the wall clock moves by more than 5 minutes while a timer runs, the engine records it in `metadata.extra["clock_jump"]` for later review.

## D10. Week starts Monday, ISO week numbering, local time zone at evaluation time

Week boundaries are computed with the user's current calendar and time zone at the moment of evaluation (`WeekSpec`). Daylight saving makes one week 167 or 169 hours long; the elapsed-time lane uses the real length. Travel across zones redraws the week in the new zone; stored timestamps are unaffected. The start weekday is a setting (default Monday) because the spec says "Monday by default".

## D11. The dual-series scale problem: two aligned lanes, not one axis

Tracked hours (20–50/week) and elapsed clock time (up to 168 h) cannot share a y-axis honestly. Grains draws two lanes sharing the x-axis (the seven days): the main lane plots cumulative tracked hours on an hours scale that auto-fits (minimum ceiling 10 h, rounded up to a multiple of 5); a thin lane beneath draws week-elapsed as a 0–100% progress line that advances with the clock, labeled with the percentage. The optional 40 h target trajectory is drawn in the main lane because it *is* in hours. Nothing pretends elapsed time is comparable to tracked hours on the same axis; the user can still read "I'm 40% through the week with 14 h tracked" at a glance.

## D12. Spacebar: control mode / typing mode with an explicit visual mode indicator

See [interaction.md](interaction.md). Space toggles the timer only in control mode; the first printable character enters typing mode, where Space is a space; Return commits and returns to control mode; Escape exits typing mode (keeping the text) and a second Escape dismisses. The mode is shown by the caret shape (block in control, bar in typing) and a small label. Rejected: modifier chords for start/stop (slower), double-space (ambiguous with typing).

## D13. Global shortcut via `KeyboardShortcuts` (Carbon hot keys), corner trigger via a global mouse-moved monitor

`RegisterEventHotKey` needs no Accessibility permission and works in full-screen Spaces; the sindresorhus `KeyboardShortcuts` package wraps it and provides the recorder control. The corner trigger uses `NSEvent.addGlobalMonitorForEvents(matching: .mouseMoved)`, which also needs no permission, with a 350 ms dwell and a 12 pt hit zone; it is off by default and the user can pick the corner. We avoid the corners the system Hot Corners settings already use when we can detect them.

## D14. Default shortcut: ⌘Escape

Chosen by the owner. ⌥⌘Escape is Force Quit, so plain ⌘Escape is free system-wide; it is one-handed and avoids ⌥Space (Raycast's default) and ⌘Space (Spotlight). It stays user-changeable in Settings (the recorder warns on conflicts); a shortcut the user already recorded is kept.

## D15. Overlay is an `NSPanel` (non-activating, floating) hosting SwiftUI

A non-activating panel can receive key events without stealing activation from the frontmost app, so Escape returns the user exactly where they were. `canBecomeKey` is true, `hidesOnDeactivate` false; it is placed on the screen containing the mouse pointer at summon time, centered horizontally, upper third vertically. `LSUIElement` is true: no Dock icon, menu bar status item only.

## D16. Chart is custom SwiftUI `Path`/`Canvas`, not Swift Charts

Swift Charts could draw two lines but gives too little control over the Monkeytype look (hairline grid, dotted future, active point glow, draw-in animation). The series is a plain array of points from `GrainsReports`, so the renderer is thin and the math is tested separately.

## D17. CSV regeneration policy

The current week's file is rewritten (atomically) at most once every 5 s after a change, and at week rollover; any edit to an entry in a prior week rewrites that week's file. Exports are `Grains-YYYY-Www.csv` in the user's chosen folder (default `~/Documents/Grains`). Times are RFC 3339 with offset plus separate local date/time columns. Schema in [csv-export.md](csv-export.md).

## D18. MCP transport: stdio, bundled binary, read-only

`grains-mcp` speaks MCP over stdio (JSON-RPC 2.0, protocol version 2025-06-18), opens the database read-only, and exposes read-only tools only. Claude Code: `claude mcp add grains -- /Applications/Grains.app/Contents/MacOS/grains-mcp`. Claude Desktop: same binary in `claude_desktop_config.json`. ChatGPT: as of October 2026 ChatGPT connectors/apps require a remote HTTPS MCP server; a localhost stdio server is not reachable from ChatGPT, so v1 documents an opt-in bridge (expose over Streamable HTTP behind a tunnel the user controls) rather than pretending it works out of the box. Details in [mcp-server.md](mcp-server.md).

## D19. Sparkle 2 via SwiftPM, feed on GitHub raw, releases on GitHub

Identical to Steam Shelf: EdDSA key in the login keychain, `appcast.xml` at repo root served from raw.githubusercontent.com, zips attached to GitHub releases, `scripts/release.sh` does archive → re-sign Sparkle helpers → notarize → staple → appcast → tag → release. Build number is the git commit count.

## D20. Minimum macOS 15, Swift 6 strict concurrency

Matches the owner's other apps; macOS 15 gives us `@Observable`, `ContinuousClock`, modern SwiftUI window APIs. Strict concurrency makes data races compile errors across the three processes' shared code.

## D21. Typeface: system monospaced (SF Mono) for entry text and numerals

Monkeytype's default is Roboto Mono; SF Mono is already on every Mac, renders beautifully at the overlay's large size, has tabular numerals, and avoids bundling a font. A bundled Roboto Mono option is on the roadmap.

## D22. History editing is minimal but present in v1

The spec defers project management but the graph section requires backdated corrections. v1 includes a History window (menu bar) listing entries by week with inline editing of start/stop and soft delete. No rates, clients directory or invoicing.

## D23. One-running index is on `(stopped_at IS NULL)`, not on `stopped_at`

data-model.md first drafted `CREATE UNIQUE INDEX entries_one_running ON entries(stopped_at) WHERE stopped_at IS NULL AND deleted_at IS NULL`. That index enforces nothing: SQLite treats NULLs as distinct in UNIQUE indexes, so every running row is "unique" (verified: two running rows insert fine). The shipped v1 migration uses the same name and WHERE clause on the expression `((stopped_at IS NULL))`, which is constant (1) for every indexed row, so a second running entry fails with `UNIQUE constraint failed: index 'entries_one_running'`. Both stores surface that as `EntryStoreError.anotherEntryRunning`. data-model.md should be updated to match.

## D24. Metadata JSON: sorted keys, Unix-seconds dates, undecodable blobs preserved

`metadata` is encoded with `.sortedKeys` (and unescaped slashes) and dates as `.secondsSince1970` so `recovered.lastHeartbeat`/`noticedAt` read like the timestamp columns (the Foundation default would be seconds since 2001). A blob that fails to decode is not an error: the entry is returned with `extra["unparsed_metadata"]` holding the raw text, so one bad row never breaks a query and is not silently dropped on the next update.

## D25. `EntryWriting` grew `commit(_:)` and kv access; shared `EntryStoreError`

Members added (no existing signature changed): `commit([EntryWrite])` applies inserts/updates in one transaction with one change notification (the engine's stop-then-insert, and resume's reconcile-then-insert); `readValue(forKey:)` / `writeValue(_:forKey:)` expose the `kv` table (keys in `EntryStoreKey`) because the clean-shutdown marker had no API. `EntryStoreError` (`notFound`, `duplicateID`, `anotherEntryRunning`, `unsupportedSchemaVersion`, `notAGrainsDatabase`) is thrown by both stores; other SQLite failures surface as `SQLiteError` (code + message). Any third-party `EntryWriting` conformer must implement the three new members.

## D26. Store semantics the docs left open

- `update` bumps `updatedAt` only when the caller did not: if the passed value is not later than the stored one it becomes `max(now, stored)`.
- `search` is Unicode case-insensitive (a registered `grains_icontains` SQL function; SQLite's LIKE folds ASCII only), newest first; whitespace-only text returns `[]`.
- `clientLabels` groups with `COLLATE NOCASE` (ASCII folding, as specified), reports the most recent spelling and its `clientID`, orders by label (NOCASE), excludes entries with no client.
- `softDelete` of an unknown id throws `notFound`; of an already deleted row is a no-op. Restoring is `update` with `deletedAt = nil`.
- Heartbeat/kv writes do not post `.grainsEntriesDidChange` (they happen every 30 s and change no entry).
- Read-only open throws for a missing file (`SQLITE_CANTOPEN`), for an uninitialized file (`notAGrainsDatabase`) and for a newer schema; it also sets `PRAGMA query_only`. Both stores take an optional injected `now` for tests.

## D27. Timer engine timing details

- `elapsed` for an entry the engine starts is purely monotonic from zero. For an entry it adopts at launch (clean relaunch) it is anchored to the entry's wall-clock age at that moment, then advances monotonically; otherwise the counter would restart at 0:00:00 after every quit. `reload()` re-anchors after the History window edits the running entry.
- A heartbeat is written immediately when an entry starts or is adopted, then every interval; the schedule is anchored when it is created and catches up rather than bursting after a long suspension. A late heartbeat after `prepareForCleanShutdown()` or a stop is discarded (generation token).
- `clock_jump` = cumulative signed integer seconds of (wall delta minus monotonic delta) for each heartbeat pair beyond 5 min; `long_sleep` = cumulative integer seconds of each wake over 2 h. The default clock is `ContinuousClock`, which advances during system sleep, so sleep alone never registers as a clock jump.
- `states()` buffers the newest 64 values; ticks land on whole elapsed seconds.

## D28. Timer engine command semantics

- `start(rawText:)` with whitespace-only text throws `TimerEngineError.emptyText` (the UI uses `toggle()` for an empty line).
- Starting any new work clears the in-memory `recovered` notice; the row keeps `reconciled = false` so it stays flagged for later review.
- At launch with nothing running, an unreconciled recovered entry that is still the most recent entry is surfaced again as `recovered` (the user quit without answering the notice).
- No heartbeat at all, or a heartbeat for a different entry, means zero credit: stopped at `startedAt`, `recovered.lastHeartbeat = startedAt`.
- `undoLastStop()` (⌘Z) is single-level and only undoes a `stop()` made in this session while idle: it starts a new entry with that text at `now` (the gap is not counted; the stopped record is untouched). It returns nil otherwise, which keeps it distinct from `toggle()`.

## D30. "As of now" views clip at now; record views use stored timestamps

`WeekSeries` and `Stats` clip every entry to `[bounds.start, min(now, bounds.end))`, so actuals never extend into the future even if a stopped entry has a stop time after `now` (clock skew, hand edit). `Aggregator` and `CSVExporter` report records as stored (`Entry.seconds(within:asOf:)` semantics: only a running entry ends at `now`). For ordinary data the two agree. A week that has not started yet has the single series point `(week.start, 0)` and `elapsedFraction` 0.

## D31. Overlap handling in reports

Overlapping intervals are merged before summing everywhere in `GrainsReports`, so overlapping time counts once. `WeekSeries`/`Stats.weekHours` merge across all entries; `Stats.byClient` and `Aggregator` merge within one client/bucket only, so per-client sums can exceed the week total only when entries for *different* clients overlap. `AggregateRow.entryCount` counts entries contributing more than 0 s to the bucket. The CSV is per entry and never merges (it is a record export). Client grouping uses `clientText` exactly (no case folding); normalization belongs to `clientID`.

## D32. CSV export details the schema left open

- Timestamps are truncated to whole seconds *before* both formatting and duration arithmetic, so `duration_seconds` always matches the printed timestamps and the two halves of a week-crossing session sum exactly to `whole_duration_seconds`.
- A row is included when the entry overlaps the week or starts inside it (zero-length entries are not lost). Rows are ordered by `started_at`, then `id` string.
- UUIDs are uppercase (`UUID.uuidString`). Every record, including the last, ends in `\n`. A field is quoted when it contains `,`, `"`, `\n` or `\r`.
- `hours` is computed in integers, rounded half up to 2 decimals. UTC offset is written `+00:00` (not `Z`) so the column shape is constant.
- Local date/time columns and RFC 3339 strings use a Gregorian, `en_US_POSIX` calendar in `WeekSpec.calendar.timeZone`, regardless of the user's calendar or locale (no `DateFormatter`/`ISO8601DateFormatter`).
- `recovered` is `true` only when `metadata.recovered` exists and `reconciled == false`.

## D33. Aggregator keys and ordering (MCP `aggregate`)

Keys: `day` → `yyyy-MM-dd` (local), `week` → ISO id of the spec week, `client` → the label or `(no client)` (with `clientText` nil), `clientDay` → `yyyy-MM-dd|<label>`. Buckets are clipped to the requested range and empty buckets are omitted. Order: day/week chronological; client by seconds descending then label (nil last); clientDay by day, then seconds descending, then label. `hours` is rounded to 2 decimals; `seconds` is exact.

## D34. Week construction details

`Week.days` are built by `calendar.date(byAdding: .day)` + `startOfDay` (never 86 400 s arithmetic); `startsOn` outside 1...7 is wrapped. `Week.previous/next` step via the instant just before the start / at the end. `Week` is also `Codable` for MCP payloads. `WeekSeries` additionally exposes `dailyHours` (7 values) and `targetLine`, and the ceiling rule is public as `WeekSeries.hoursCeiling(trackedHours:targetHours:)`. `Stats.byClient` is `[ClientHours]` instead of the tuple in the original sketch so it is `Equatable`/`Codable`.

## D40. GrainsMCP protocol handling details

`MCPServer(store:spec:exportDirectory:options:)` is an immutable `Sendable` final class; `handle(_ requestJSON: Data) -> Data?` maps one message to one compact response line (nil for notifications), and `runStdio()` adds newline-delimited framing. JSON is a hand-written `JSONValue` with its own serializer: object keys always sorted, the compact form never contains a raw newline, identical input gives identical bytes. Choices the spec left open:
- `initialize` always answers `protocolVersion: "2025-06-18"` (the only revision implemented) and includes `instructions` with the Grains conventions. Requests are served even before `initialize` (no session gating; stdio has one client).
- Batches (a JSON array) → one `-32600` error with `id: null` (batching was removed in 2025-06-18). `"id": null`, a non-object message, a wrong `jsonrpc` or a missing `method` → `-32600`. Malformed JSON → `-32700`, `id: null`.
- Messages without `id` are never answered, whatever the method; client responses (`result`/`error`, no `method`) are ignored.
- `resources/list`, `resources/templates/list` and `prompts/list` return empty lists; capabilities advertise only `tools` (`listChanged: false`).
- Each tool result has one `text` content item with the pretty-printed (sorted keys) JSON and `structuredContent` with the same object, plus `isError: false`. Tools carry `annotations.readOnlyHint = true`. No `outputSchema` in v1.

## D41. Protocol errors versus tool errors

`-32602` is used only when the `tools/call` envelope is wrong: `params` not an object, no string `name`, unknown tool name (as the MCP spec prescribes), `arguments` not an object. Everything about argument *values* (missing required argument, wrong JSON type, out-of-range limit, unparseable date, `to` not after `from`, unknown `group_by`, invalid week id, malformed or unknown session id) is a tool result with `isError: true` and a readable message, so the model can correct itself. Undeclared extra arguments are ignored at runtime even though the schemas say `additionalProperties: false`. Database failures are also `isError` results ("Could not read the Grains database: ...").

## D42. `--redact-notes` semantics

Applied to every output, including the `export_week` CSV: the `note` key is omitted from session objects (CSV `note` column empty), and `raw_text` is replaced by `client_text`, or `[redacted]` when the entry has no client. `search_sessions` then matches only `client_text`, because matching hidden text would reveal it through the hit list. Totals and client labels are unaffected.

## D43. Tool date inputs and time output

Inputs accept `YYYY-MM-DD` (a local day in `WeekSpec.calendar.timeZone`) or RFC 3339 `YYYY-MM-DDTHH:MM:SS[.fraction](Z|±HH:MM)` (`T`, `t` or a space as separator; an offset is required). `from` is inclusive, `to` exclusive; a date-only `to` means the next local midnight, so the day is included (a 25 h DST day stays 25 h). Impossible dates (Feb 30, hour 25) are rejected rather than rolled over. Output times use the CSV's formatting rule (D32): whole seconds, truncated, numeric offset (`+00:00`, never `Z`). Seconds fields are the exact values from `Entry.duration(asOf:)`/`seconds(within:asOf:)` and `Aggregator`; hours are rounded to 2 decimals with the `AggregateRow.hours` rule.

## D44. `export_week` week resolution

A week id resolves to the `WeekSpec` week whose `isoIdentifier` equals it, i.e. the week whose first day lies in that ISO week, which is exactly the week the app's `Grains-<id>.csv` covers. With the default Monday start that is the week containing the ISO week's Monday; for other start days, the week containing that Monday can carry the *previous* id (a Sunday-start week containing Monday Oct 26 starts Sun Oct 25 = 2026-W43), so the server takes the following week instead (Sun Nov 1 for 2026-W44). Entries are fetched over the week widened by one second at the start so a zero-length entry at the week start is not lost (D32), then `CSVExporter.csv(for:entries:now:)` produces the text unchanged. `structuredContent` carries `week`, `file_name`, `start`, `end`, `time_zone`, `row_count` and `csv`.

## D45. Tool output shapes the table left open

- Session object: `id`, `raw_text`, `client_text`, `client_id`, `note` (absent when redacted), `started_at`, `stopped_at` (null while running), `running`, `duration_seconds` (whole session as of now), `recovered` (unreconciled recovery, same rule as the CSV), and in `list_sessions` also `seconds_in_range`.
- `list_sessions`: `limit` 1–1000 (default 200), `client` is a case-insensitive exact match on `client_text`; returns `count`, `total_matching`, `truncated`. `search_sessions`: `limit` 1–500 (default 50), newest first.
- `aggregate`: `total_seconds`/`total_hours` are the merged total over the whole range (sum of the day buckets), so for `client` grouping the rows can sum to more than the total when different clients overlap (D31). For a full week the total equals `WeekSeries.totalHours` (tested).
- `list_client_labels`: the store's `clientLabels()` excludes unlabeled entries, so the `client_text: null` row is computed from all live entries; totals are whole durations as of now (running entries included).
- `current_week`: `total_hours` and per-day `hours` rounded to 2 decimals, `elapsed_fraction` to 4, plus `week_length_hours`, `running`, and with `target_hours` the on-pace `target_hours_at_now` (target × elapsed fraction).
- `list_exports`: files named `Grains-*.csv`, sorted by name; `week` is null when the name has no `YYYY-Www` after the prefix; a missing folder is `exists: false`, not an error.

## D46. `grains-mcp` command line

Flags: `--db <path>` (else `GrainsPaths.databaseURL`, which honors `GRAINS_DB_PATH`), `--export-dir <path>` (else `~/Documents/Grains`), `--redact-notes`, `--week-start <1-7>` (default 2, Monday; calendar `.autoupdatingCurrent`), `--version`, `--help`. Exit codes: 0 on stdin EOF or when stdout is closed, 2 when the database is missing ("Grains database not found at <path>. Launch Grains once to create it.") or cannot be opened read-only, 64 for usage errors. SIGPIPE is ignored so a closed stdout becomes a write error and a clean exit. The `--http` transport is not implemented (roadmap). Note: `GrainsPaths.databaseURL` creates `~/Library/Application Support/Grains/` as a side effect even in the MCP process; harmless, but the server never creates the database file.

## D50. Key-table details interaction.md left open

- ⌫ in control mode enters typing mode **and** deletes the character before the caret (one keystroke does what it says); it does not clear a committed line. Any other printable clears a committed line first.
- Return in typing mode on an empty/whitespace line only returns to control mode (the engine rejects empty text, D28).
- ⌘Z in typing mode does nothing (single-level ⌘Z is "undo stop", a control-mode command; there is no text undo in v1).
- Added beyond the tables: ⌘C/⌘X copy/cut (selection, or the whole line for ⌘C in control mode), ⌘V in control mode enters typing and pastes, ⌘W hides like Escape. ↑/↓ in typing mode move to line start/end (single-line field convention), not recent cycling.
- R/A are the recovery keys only in control mode while a recovered entry is pending (either case); otherwise they are ordinary letters.
- The typing-mode label reads `return to switch` while an entry runs, `return to start` otherwise.
- The hot key on an overlay that is visible but no longer key (the user clicked elsewhere with "hide when I click elsewhere" off) refocuses it instead of hiding it.
- Key routing: Space/Return/Escape are taken by key code before the input system (except while composing marked text); ⌘ shortcuts in `performKeyEquivalent`; everything else goes through `interpretKeyEvents`, so movement/deletion follow the user's key bindings and dead keys/IMEs work via `NSTextInputClient`.

## D51. Entry line fits by shrinking, then scrolls

At 28 pt SF Mono only ~34 characters fit in the 584 pt line; typical entries (`Global Credit Union - Jamf certificate troubleshooting`, 54) do not. The line shrinks in 1 pt steps from 28 to 18 pt to show the whole entry, and beyond that scrolls horizontally to keep the caret visible. The line box keeps the 28 pt height so the layout never jumps. Rejected: wrapping (breaks "one continuous line"), fixed 28 pt with scrolling (hides the client portion).

## D52. Overlay window geometry

The panel is larger than the card (70 pt sides, 40 pt top, 100 pt bottom, card area up to 470 pt) so the design's 0 24 60 shadow is drawn by SwiftUI; the transparent margin passes clicks through and the panel never resizes with content. The card's top edge is at 22% of the pointer screen's full height from the top, clamped below the menu bar. Entrance/exit are SwiftUI animations of the card (the window is ordered out after the 90 ms fade; a show during the fade cancels it).

## D53. History restore is limited to this session

`EntryReading` excludes soft-deleted rows everywhere and has no "list deleted" call, and the app may not change the core API. The History window therefore offers Undo Delete and a "Deleted in this session" list with Restore (restore = `update` with `deletedAt = nil`, D26). A core `deletedEntries(overlapping:)` would allow a persistent trash view; revisit then. Editing text rewrites `rawText` only when the user changed the text field, then re-parses client/note.

## D54. ExportService details

- Debounce is coalescing: the first change for a week opens a 5 s window and later changes ride along, so a week is written at most once per 5 s and a stream of edits cannot postpone the write forever.
- The service remembers which weeks each entry occupied when last seen, so an edit that moves an entry, or a delete (the deleted row can no longer be read), also rewrites the old week. At launch every live entry is primed (D61); "Export all weeks now" repairs anything missed.
- A week with no entries is written only if its file already exists (deleting a week's last entry empties the file; empty weeks create no files).
- `GRAINS_EXPORT_DIR` overrides the folder (development, so dev databases never write into `~/Documents/Grains`); Settings then shows the folder read-only.

## D55. Claude configuration mirrors the app's settings

"Copy Claude Code command" / "Copy Claude Desktop JSON" use `Bundle.main.bundleURL/Contents/MacOS/grains-mcp` and add `--redact-notes` when "Share notes with AI" is off, `--export-dir <path>` when the export folder is not the default, and `--week-start <n>` when the week does not start on Monday (flags from D46), so the AI sees the same weeks and files as the overlay. A pasted snippet does not follow later settings changes; copy again after changing them.

## D56. Overlay layout choices

- The 44 pt counter is the session metric (labeled SESSION); the right side shows WEEK and TODAY at 22 pt. While navigating to another week the WEEK label becomes that week's ISO id and the chart header shows it; TODAY and SESSION stay live. → cannot move past the current week.
- A 14 pt chart header row carries the ceiling label (`20h`, left) and the elapsed label (`62% of week`, right, in the elapsed color) so neither collides with the lanes.
- The tracked line is accent while running and neutral (`text`) otherwise; the current-moment point is shown in both (glowing only while running).
- The block caret is drawn behind the text, the bar caret in front; the caret slides 70 ms between positions (off with Reduce Motion).

## D57. Development launch arguments

`--show` opens the overlay at launch; `--demo-state idle|typing|running|stopped` sets up a state (running/stopped write real entries, so use a dev database); `--snapshot <path>` writes a PNG of the panel content and quits (used for documentation screenshots because `screencapture` needs Screen Recording permission). Sparkle's updater is not started in demo/snapshot runs, and the whole app setup is skipped when the process hosts XCTest so `GrainsAppTests` never opens the real database or registers the hot key.

## D58. Corner trigger defaults

Default corner is bottom-left (top corners collide with the menu bar and Notification Center). The Hot Corners check (`com.apple.dock` `wvous-*-corner` not 0/1) runs whenever the trigger is configured and when Settings opens; a conflicting corner stays selectable but inactive, with a note. The trigger fires only when the overlay is not already visible.

## D60. Clean shutdown is synchronous in `applicationWillTerminate`

`applicationShouldTerminate` returns `.terminateNow`; `applicationWillTerminate` flushes pending CSV writes (`ExportService.flushSync()`) and then calls `TimerEngine.prepareForCleanShutdownSync()`, which writes `clean_shutdown = "1"` then clears the heartbeat directly through the (synchronous, thread-safe) store, in the same order as the async version. Replaces the earlier `.terminateLater` + `Task` reply: when `terminate:` is called from a main-queue job (any main-actor Task, Sparkle's relaunch handler, the `--snapshot` path) AppKit's nested run loop does not drain the main dispatch queue, so the reply never came, the app hung and the marker stayed 0. The sync variant does not stop the engine's heartbeat task; the process exits right after, so no heartbeat can follow. The `--snapshot` path also calls `terminate` via `RunLoop.main.perform`. The async `prepareForCleanShutdown()` stays for callers that can await.

## D61. Export knows pre-launch entries' weeks; pending writes flush on quit

`ExportService.start()` primes the known weeks of every live entry overlapping `earliestStart … now + 7 days`, so a delete or move of an entry from before this launch rewrites its old week (previously only entries seen in this session were known, and the deleted row can no longer be read, so the CSV stayed stale). A changed id the store no longer returns schedules its last known weeks. On quit, `flushSync()` cancels the debounce timers and writes the pending weeks on the main thread. The last write error is shown in Settings; "Export all weeks now" reports written and failed counts.

## D62. Key auto-repeat is ignored for control-mode commands

`KeyCaptureView` forwards `NSEvent.isARepeat` with each input; `InputStateMachine` drops repeats of Space, Return, Escape, whitespace text and the arrow/navigation commands in control mode (holding Space used to toggle every ~30 ms and create bursts of entries). Typing mode keeps repeats (held Space, ⌫, arrows edit as usual). Repeated printable keys and ⌫ in control mode still enter typing.

## D63. No key input during the hide fade

The panel stays key for the ~100 ms exit fade; keys arriving once `presentation.isPresented` is false are dropped instead of reaching the model.

## D64. A stop does not commit the line; future stop times are rejected

`AppModel.toggleTimer` marks the line committed only when it starts an entry (decided inside the serialized command chain). A draft typed while running, Escaped, then Space stops the timer and stays a draft, not the stopped entry's text. History rejects an edited stop time later than now ("The stop time is in the future."), like a future start.
