# Decisions log

Numbered, append-only. Each entry says what was decided, why, and what would make us revisit it. Agents and humans editing the code must add an entry when they make a choice the spec left open.

## D1. Name: Grains

The spec calls the product Blink; the owner renamed it Grains before any code existed. Bundle id `net.outofajam.Grains`, repo `begemotike/grains`, CSV files `Grains-2026-W44.csv`, MCP server `grains-mcp`. The spec file is kept verbatim under `docs/spec/` with its original name.

## D2. Monorepo: one Swift package plus one XcodeGen app project

The testable core lives in a Swift package (`GrainsCore`, `GrainsReports`, `GrainsMCP`, `grains-mcp`) so `swift test` runs with no simulator, no signing and no Xcode project. The app target is generated by XcodeGen from `project.yml` (same approach as Steam Shelf) and depends on the package by local path. Why: the spec requires "the core independently testable" and the MCP server is a second process that must share code with the app without sharing a UI framework.

## D3. No App Sandbox in v1 (hardened runtime on)

Distribution is Developer ID + notarization, not the App Store, so the sandbox is optional. It was turned off because: (a) the bundled `grains-mcp` is launched by Claude Code / Claude Desktop as an ordinary process and must read the same database file the app writes; a container path works but is fragile and confusing in client configs; (b) the user-chosen CSV export folder would need security-scoped bookmarks; (c) Sparkle needs XPC exceptions when sandboxed. Revisit if we ever target the App Store. Hardened runtime stays on in Release.

## D4. Database location

`~/Library/Application Support/Grains/grains.sqlite` (WAL mode). Shared by the app (read/write) and `grains-mcp` (read-only, `SQLITE_OPEN_READONLY`, WAL makes concurrent readers safe). Override with `GRAINS_DB_PATH` for tests and development.

## D5. Raw SQLite3 via a thin internal wrapper, no ORM

The schema is one table plus a key/value table. A dependency such as GRDB would add a large framework to notarize and re-sign for a dozen queries. The wrapper is ~200 lines, fully covered by tests, and uses prepared statements only.

## D6. Durations are computed, never authoritative

`duration_seconds` exists as a stored column for CSV/MCP convenience but is recomputed from `started_at`/`stopped_at` on every write, and every total, chart point and export column is built from `Entry.seconds(within:asOf:)`. This is what makes midnight/week-boundary splitting and backdated corrections deterministic.

## D7. Timer survives everything except an explicit stop

Closing the overlay, switching apps, locking, sleeping and quitting the app do **not** stop a running entry; the row simply has `stopped_at NULL` and absolute timestamps. On relaunch after a clean quit the entry is still running from its original start. Only a crash (no clean-shutdown marker) triggers recovery (D8).

## D8. Crash recovery: stop at last heartbeat, flag, never invent time

While an entry runs the app writes a heartbeat every 30 s. On launch, if an entry is running and the previous session did not shut down cleanly, the entry is stopped at the last heartbeat and `metadata.recovered` is set (last heartbeat, noticed-at, reconciled=false). The overlay shows a one-line "recovered" notice with Resume. The gap between heartbeat and launch is uncertain and is not counted. A clean quit clears the heartbeat and leaves the entry running (D7).

## D9. Live elapsed display uses monotonic time, records use wall-clock

The running-session counter in the overlay is driven by `ContinuousClock` offsets from the moment the engine observed the start, so a wall-clock jump (NTP, time-zone travel, manual change) does not make the counter jump backwards or forwards mid-session. Stored records use absolute `Date`s. If the wall clock moves by more than 5 minutes while a timer runs, the engine records it in `metadata.extra["clock_jump"]` for later review.

## D10. Week starts Monday, ISO week numbering, local time zone at evaluation time

Week boundaries are computed with the user's current calendar and time zone at the moment of evaluation (`WeekSpec`). Daylight saving makes one week 167 or 169 hours long; the elapsed-time lane uses the real length. Travel across zones redraws the week in the new zone; stored timestamps are unaffected. The start weekday is a setting (default Monday) because the spec says "Monday by default".

## D11. The dual-series scale problem: two aligned lanes, not one axis

Tracked hours (20–50/week) and elapsed clock time (up to 168 h) cannot share a y-axis honestly. Grains draws two lanes sharing the x-axis (the seven days): the main lane plots cumulative tracked hours on an hours scale that auto-fits (minimum ceiling 10 h, rounded up to a multiple of 5); a thin lane beneath draws week-elapsed as a 0–100% progress line that advances with the clock, labeled with the percentage. The optional 40 h target trajectory is drawn in the main lane because it *is* in hours. Nothing pretends elapsed time is comparable to tracked hours on the same axis; the user can still read "I'm 40% through the week with 14 h tracked" at a glance.

## D12. Spacebar: control mode / typing mode with an explicit visual mode indicator

See [interaction.md](interaction.md). Space toggles the timer only in control mode; the first printable character enters typing mode, where Space is a space; Return commits and returns to control mode; Escape exits typing mode (keeping the text) and a second Escape dismisses. The mode is shown by the caret shape (block in control, bar in typing) and a small label. Rejected: modifier chords for start/stop (slower), double-space (ambiguous with typing).

## D13. Global shortcut via `KeyboardShortcuts` (Carbon hot keys), corner trigger via a global mouse-moved monitor

`RegisterEventHotKey` needs no Accessibility permission and works in full-screen Spaces; the sindresorhus `KeyboardShortcuts` package wraps it and provides the recorder control. The corner trigger uses `NSEvent.addGlobalMonitorForEvents(matching: .mouseMoved)`, which also needs no permission, with a 350 ms dwell and a 12 pt hit zone; it is off by default and the user can pick the corner. We avoid the corners the system Hot Corners settings already use when we can detect them.

## D14. Default shortcut: ⌥Space

Fast to hit with one hand; does not collide with Spotlight (⌘Space) or Raycast's default (⌥Space is Raycast's default too, so the recorder warns when a conflict is detected and the shortcut is trivially changeable).

## D15. Overlay is an `NSPanel` (non-activating, floating) hosting SwiftUI

A non-activating panel can receive key events without stealing activation from the frontmost app, so Escape returns the user exactly where they were. `canBecomeKey` is true, `hidesOnDeactivate` false; it is placed on the screen containing the mouse pointer at summon time, centered horizontally, upper third vertically. `LSUIElement` is true: no Dock icon, menu bar status item only.

## D16. Chart is custom SwiftUI `Path`/`Canvas`, not Swift Charts

Swift Charts could draw two lines but gives too little control over the Monkeytype look (hairline grid, dotted future, active point glow, draw-in animation). The series is a plain array of points from `GrainsReports`, so the renderer is thin and the math is tested separately.

## D17. CSV regeneration policy

The current week's file is rewritten (atomically) at most once every 5 s after a change, and at week rollover; any edit to an entry in a prior week rewrites that week's file. Exports are `Grains-YYYY-Www.csv` in the user's chosen folder (default `~/Documents/Grains`). Times are RFC 3339 with offset plus separate local date/time columns. Schema in [csv-export.md](csv-export.md).

## D18. MCP transport: stdio, bundled binary, read-only

`grains-mcp` speaks MCP over stdio (JSON-RPC 2.0, protocol version 2025-06-18), opens the database read-only, and exposes read-only tools only. Claude Code: `claude mcp add grains -- /Applications/Grains.app/Contents/MacOS/grains-mcp`. Claude Desktop: same binary in `claude_desktop_config.json`. ChatGPT: as of October 2026 ChatGPT connectors/apps require a remote HTTPS MCP server; a localhost stdio server is not reachable from ChatGPT, so v1 documents an opt-in bridge (expose over Streamable HTTP behind a tunnel the user controls) rather than pretending it works out of the box. Details in [mcp-server.md](mcp-server.md).

## D19. Sparkle 2 via SwiftPM, feed on GitHub raw, releases on GitHub

Identical to Steam Shelf: EdDSA key in the login keychain, `appcast.xml` at repo root served from raw.githubusercontent.com, zips attached to GitHub releases, `scripts/release.sh` does archive → re-sign Sparkle helpers → notarize → staple → appcast → tag → release. Build number is the git commit count.

## D20. Minimum macOS 15, Swift 6 strict concurrency

Matches the owner's other apps; macOS 15 gives us `@Observable`, `ContinuousClock`, modern SwiftUI window APIs. Strict concurrency makes data races compile errors across the three processes' shared code.

## D21. Typeface: system monospaced (SF Mono) for entry text and numerals

Monkeytype's default is Roboto Mono; SF Mono is already on every Mac, renders beautifully at the overlay's large size, has tabular numerals, and avoids bundling a font. A bundled Roboto Mono option is on the roadmap.

## D22. History editing is minimal but present in v1

The spec defers project management but the graph section requires backdated corrections. v1 includes a History window (menu bar) listing entries by week with inline editing of start/stop and soft delete. No rates, clients directory or invoicing.
